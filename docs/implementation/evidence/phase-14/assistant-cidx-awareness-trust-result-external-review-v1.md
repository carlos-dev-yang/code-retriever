## Review packet

Both reviewers received the same English result packet. It contained the
fixed experiment boundary, exact quality and efficiency denominators, paired
and all-cell results, deterministic journey measurements, historical context,
artifact hashes, and the proposed next decision. It contained no corpus source
body, ignored raw trace, credential, or provider request.

## Reviewer agreement

Both reviewers accepted the arithmetic and the main result:

- the quality denominator is 30 scheduled tasks per arm;
- paired efficiency uses 29 valid comparable pairs;
- the dual-complete token slice uses 28 pairs;
- trust-priority improved answer completeness and claim support in this panel;
- trust-priority substantially reduced unique source inspected;
- trust-priority did not reduce the full investigation journey because actions,
  cidx calls, and paired model-total usage increased; and
- the result cannot support a general efficiency or promotion claim.

Both reviewers also agreed that the aware arm's all-cell token total includes a
zero-usage timeout. That total is descriptive workload accounting only; the
29-pair estimates remain the efficiency authority.

## Adopted interpretation correction

The result must not say that trust-priority improved stopping behavior. The
trace shows that cost accumulated after useful locator selection, but it does
not isolate unnecessary continuation from legitimate dependency expansion.
The adopted wording is:

> The dominant measured loss after successful locator selection is
> evidence-acquisition/orchestration. This run does not isolate stopping from
> evidence acquisition.

The result document uses this narrower claim.

## Next candidate

ChatGPT recommended the smallest intervention that directly addresses the
measured 125 individual trust-arm reads: allow one bounded request to accept a
small set of already returned locators and return each result as a separate,
line-addressable evidence unit. Retrieval, ranking, queries, truth, prompt
policy, and the number of distinct facts remain unchanged.

Grok also preferred an evidence-acquisition intervention, but proposed a wider
four-arm study. That expansion is not adopted. It would change more than one
factor, exceed the requested two-arm simplification boundary, and make the
60-turn accounting internally inconsistent. If the owner authorizes another
experiment, it should compare the current single-locator trust arm with one
bounded multi-locator evidence-handoff arm only.

A ready-to-use locator reference is not the first candidate. This run had no
incomplete cidx call or locator-hash copy failure, so locator reconstruction is
not the measured bottleneck.

## Required gates for any authorized successor

1. No regression in complete answers, required-group coverage, unsupported
   claims, or contradicted claims.
2. Fewer evidence requests, duplicate reads, and overlapping reads without
   losing evidence coverage or allowing uncontrolled source-byte growth.
3. Lower paired repository actions and official model-total/uncached-input
   usage under the same failure-safe denominators.

## Claims explicitly prohibited

This result does not establish general efficiency, improved stopping, an FTS
bottleneck, universal locator sufficiency, a proven batching solution, or
generalization beyond the frozen repositories, questions, model, FTS state,
prompt, and configuration.

## Decision boundary

The review does not authorize that implementation. The owner must first choose
the request bound and whether the experiment extends `read_span` or uses a
separate versioned interface. No new repository, dense/hybrid work, retrieval
retuning, semantic-review system, or paid provider action follows from this
